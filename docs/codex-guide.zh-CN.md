# Codex 应用使用指南（中文）

本指南只讲 **Codex 桌面应用（App）**——图形界面、鼠标操作、ChatGPT 账号登录，**不涉及任何命令行**。内容涵盖安装登录、权限（含"绕过权限"）、仓库结构约定、核心功能，以及如何用**提示词**把市场调研、自动化 agent 等工作一键跑起来。

> 提示：Codex 应用迭代很快，界面文案与位置可能随版本变化；遇到不一致时以应用内实际选项为准。

## 1. 什么是 Codex 应用

Codex 应用是 OpenAI 的编码智能体（coding agent）的**桌面版**，在 **macOS 与 Windows** 上都能用（Windows 版自 2026 年 3 月起提供）。它把 agent 能力装进一个专注的图形界面：

- 用**线程（thread）**组织任务，可同时开多个、并行推进；
- 每个线程在独立的 **Git worktree** 里改代码，互不干扰；
- 内置**浏览器**，agent 能真正打开网页操作；
- 支持**自动化（Automations）**、产物预览、插件与技能；
- 权限、沙箱全部由应用托管，你**不用敲任何命令**。

一句话：**打开应用 → 选仓库 → 用中文说需求 → agent 干活**。

---

## 2. 安装与登录

三步搞定，全程图形界面：

1. **下载 Codex 应用**并安装（macOS / Windows；企业可由管理员通过 Microsoft Store + MDM 统一分发）。
2. 打开应用，点 **Sign in with ChatGPT**，用 **ChatGPT 账号登录**即可——ChatGPT **Plus / Pro / Business / Edu / Enterprise** 套餐都包含 Codex。（也支持用 OpenAI API Key 登录。）
3. 授权应用访问你的本地项目文件夹，准备开始。

> **Windows 说明**：应用在 Windows 上原生运行，沙箱与隔离由应用自动管理；若你需要 Linux 原生环境，可在应用设置里把运行环境切换到 **WSL2**。这些都在界面里点选完成，无需命令行。

---

## 3. 快速开始

1. 在应用里点 **Open folder / 打开文件夹**，选择你的项目仓库。
2. 点 **New thread / 新建线程**，在输入框里用自然语言描述任务，例如：

   ```
   帮我把 src/utils/date.ts 里的时区处理改成使用 UTC，并补充单元测试。
   ```

3. Codex 会分析代码、给出计划，并按当前**权限模式**执行（见下一节）。
4. 完成后在线程里**查看 diff**、预览产物，满意就提交。

想同时做几件事？**再开一个线程**即可——多个线程并行，各自独立。

## 4. 权限模式与绕过权限

这是使用 Codex 最重要的概念。应用把权限收敛成**三档模式**，在每个线程的**权限菜单**里随时切换：

| 模式 | 能做什么 | 适用场景 |
|------|----------|----------|
| **Read Only（只读）** | 只能读代码、聊天、规划，**不改任何文件**。 | 方案设计、代码审阅、市场调研收集信息 |
| **Auto（自动）** | 在工作目录内自动读文件、改代码、跑命令。 | 日常开发（**推荐默认**） |
| **Full Access（完全访问）** | **解除沙箱**：可访问系统任意文件并联网。 | 仅限隔离环境 |

### 绕过权限 = 切到 Full Access ⚠️

所谓"绕过权限"，在应用里就是把线程切到 **Full Access**——它移除全部沙箱限制，让 agent 能读写系统任意文件并联网。

> ⚠️ **请把 Full Access 当作 `sudo` 看待**
> - 威力大、也危险：agent 可以删文件、访问网络、动工作目录以外的任何东西。
> - **只应**在受控/隔离环境使用：Docker 容器、一次性虚拟机、实验性分支。
> - 日常开发请用 **Auto**——它已经足够顺手，且保留了工作目录沙箱这层基本防护。
> - 需要真正强隔离时，在应用设置里切到 **WSL2** 或在容器中运行。

### 小技巧：按任务选模式

- **做调研 / 审代码 / 让它先出方案** → 用 **Read Only**，零风险，绝不会误改文件。
- **日常写代码、改 bug、加测试** → 用 **Auto**。
- **一次性的高权限重活**（如全局脚本、跨目录操作）→ 在隔离环境里用 **Full Access**。

## 5. 仓库结构约定

Codex 会自动读取项目里的约定文件，用它"了解你的规矩"。好的结构能显著提升表现。

### `AGENTS.md` — 给智能体的项目说明

在仓库根目录放一个 `AGENTS.md`，Codex 每次都会读它。建议写清：

```markdown
# 项目说明（供智能体阅读）

## 技术栈
- Node.js >= 22，pnpm，TypeScript strict，ESM

## 目录结构
- src/        业务源码
- packages/   工作区子包
- tests/      测试

## 常用命令
- 安装：pnpm install
- 构建：pnpm build
- 测试：pnpm test
- 检查：pnpm lint

## 约定
- 改动要保证 `pnpm test` 与 `pnpm lint` 通过
- 不要提交 .env、密钥或构建产物
- 提交信息用中文，遵循 Conventional Commits
```

要点：
- **命令写全**，Codex 才会主动跑构建/测试来验证自己的改动。
- **写明禁区**（不要动的文件、不要提交的内容）。
- `AGENTS.md` 支持分层：子目录也可放各自的 `AGENTS.md`，就近覆盖父级说明。

### 推荐的仓库骨架

```
your-project/
├── AGENTS.md        # 给 Codex 的项目说明（必备）
├── README.md        # 面向人的说明
├── .gitignore
├── src/             # 源码
├── tests/           # 测试
├── docs/            # 文档
└── package.json     # 声明 build / test / lint 脚本
```

> 不想手写 `AGENTS.md`？直接在应用里下一条提示词：「阅读本仓库，帮我生成一份 AGENTS.md，包含技术栈、目录、命令与约定」，让 Codex 替你起草。

## 6. 应用的核心功能

| 功能 | 说明 |
|------|------|
| **并行线程（Threads）** | 同时开多个线程，多个 agent 各干各的，互不打架。 |
| **Git worktree** | 每个线程在独立 worktree 里改代码，天然隔离，方便分别 review diff、分别提交。 |
| **自动化（Automations）** | 把常用任务做成可重复的一键动作；还能**定时**运行，或**唤醒**同一线程做周期性检查。 |
| **内置浏览器 / Computer Use** | 应用自带浏览器，agent 可真正打开网页、点击操作——**市场调研**类任务的基础。 |
| **产物预览** | 直接在线程里预览生成的图表、报告、文档等产物。 |
| **插件与技能（Plugins / Skills）** | 扩展 Codex 能力，比如接入 Understand-Anything 这类理解代码库的技能。 |
| **审批与沙箱** | 三档权限模式 + 受管沙箱，安全边界一目了然（见第 4 节）。 |

## 7. 与 Understand-Anything 配合

**Understand-Anything** 是一个帮你"读懂陌生代码库"的技能——生成交互式知识图谱、引导式讲解与深度解读。它可作为技能在 Codex 中使用；安装方式见本仓库根目录的 [`README.zh-CN.md`](../READMEs/README.zh-CN.md)。

在 Codex 应用里用它的典型流程：

1. 用 **Read Only** 模式新建线程，先让 Codex 调用理解类能力**读懂整个仓库**、产出结构图与讲解；
2. 心里有数后，再切到 **Auto** 模式动手改代码。

> 只读 + 先理解，能大幅降低 agent 在陌生代码库里"改错地方"的概率。

## 8. 高效工作流技巧

把 Codex 用成**可迭代的循环**，而不是一问一答。

### 技巧 1 — 让它自己跑测试形成"改→测→修"闭环

在 `AGENTS.md` 写清测试命令后，下达带验收标准的任务：

```
实现 feature X，并确保 `pnpm test` 全部通过；若失败就自己修，直到全绿。
```

在 **Auto** 模式下，Codex 会自动进入 **编辑 → 跑测试 → 读报错 → 再修** 的循环，直到达标。

### 技巧 2 — 先规划再动手

复杂任务先用 **Read Only** 让它只出方案：

```
先只给出实现计划和涉及的文件清单，不要改任何代码，等我确认。
```

确认方向后再切 **Auto** 执行，避免大范围返工。

### 技巧 3 — 并行开线程分头干

把互不相关的任务拆到不同线程，借助 worktree 隔离**同时推进**，最后分别 review。

### 技巧 4 — 让它自我沉淀项目知识

```
完成任务后，把本次发现的项目约定 / 易错点，简洁地追加到 AGENTS.md 的"约定"小节。
```

仓库知识随使用不断累积，下次它更懂你的项目。

### 技巧 5 — 小步提交，便于回滚

```
每完成一个独立改动就提交一次，提交信息用中文说明"做了什么、为什么"。
```

出问题时能精确回退到某一步。

### 技巧 6 — 明确"完成的定义"

模糊的任务得到模糊的结果。给出可验证的验收标准：

> ❌ "优化一下性能"
> ✅ "把 `parse()` 的耗时从 O(n²) 降到 O(n log n)，并新增基准测试证明提升，测试要通过"

## 9. 用例：用提示词把一切自动化

Codex 应用的真正威力在于——**你几乎只用写"提示词（prompt）"，就能把整条流程自动化**。原则：**说清目标 + 说清产物 + 说清验收标准**，剩下交给 agent。

### 用例 A — 市场调研（Read Only + 内置浏览器）

新建线程，选 **Read Only** 模式（只读、零风险），下达：

```
你是一名市场研究员。用内置浏览器调研"面向中小团队的 AI 代码助手"市场：
1. 列出 6-8 个主要产品，整理定价、目标用户、核心卖点、明显短板；
2. 汇总成一张 Markdown 对比表，并写一段 200 字的机会点分析；
3. 每条结论后面附上来源链接。
把结果保存为 research/ai-coding-assistants.md。
```

Codex 会用内置浏览器逐个网站取证、整理成表格产物，你在应用里直接预览。只读模式保证它绝不会误改文件。

### 用例 B — 搭一个"自动化 agent"（Automations + 定时）

想要每天自检的助手？用应用的 **Automations**（自动化）把一段提示词变成定时任务：

```
每个工作日 09:00：
1. 拉取最新代码；
2. 运行 `pnpm test` 与 `pnpm lint`；
3. 若有失败，用一段中文摘要列出失败项与可能原因；
4. 把摘要追加到 reports/daily-YYYYMMDD.md。
只在有失败时提醒我。
```

保存为自动化后，它会**按时唤醒同一线程**重复执行——这就是一个"值班 agent"。同理可做：每天汇总依赖更新、每周生成变更周报、监控某网页有无更新。

### 用例 C — 从零搭项目骨架（Auto 模式）

```
帮我初始化一个 TypeScript + Vitest 的库项目：
- 生成 package.json（含 build/test/lint 脚本）、tsconfig、eslint 配置；
- 建立 src/ 与 tests/ 目录与示例文件；
- 写一份 AGENTS.md 说明技术栈、命令与约定；
- 最后跑一次 test 确认全绿，并初始化 git 提交。
```

### 用例 D — 批量重构 / 迁移（Auto + 多 worktree）

开多个并行线程，每个线程在独立 worktree 里处理一个子包，互不干扰：

```
把 packages/ 下所有子包从 CommonJS 迁移到 ESM，逐包修改并保证各自构建通过；
每完成一个子包就提交一次，说明改了什么。
```

### 写好提示词的通用配方

> **角色 + 目标 + 步骤 + 产物 + 验收 + 边界**
> - **角色**：你是一名市场研究员 / 资深后端工程师……
> - **目标**：要解决的问题，一句话说清。
> - **步骤**：拆成有序小步，降低跑偏概率。
> - **产物**：明确落到哪个文件、什么格式（表格 / 报告 / 代码）。
> - **验收**：可验证的完成标准（"测试全绿""附来源链接"）。
> - **边界**：不要动什么、失败时怎么办、需不需要先给计划。

把这套配方写进 `AGENTS.md` 或自动化里，Codex 就能稳定复现你要的结果——**一切皆可由提示词驱动**。

## 10. 常见问题

**Q：每一步都要我确认，太慢了怎么办？**
A：把线程切到 **Auto** 模式——它在工作目录内自动干活，只在必要时才问你。

**Q：怎么"绕过权限"？安全吗？**
A：绕过权限就是切到 **Full Access**，它关闭全部沙箱防护。只应在 Docker 容器 / 一次性 VM / 实验分支里对可信任务使用。日常请用 **Auto**。

**Q：只想让它读代码、不改文件？**
A：用 **Read Only** 模式，最适合规划、审阅与调研。

**Q：Codex 改错了怎么办？**
A：养成小步提交的习惯（技巧 5），在线程里查看 diff，用 Git 精确回退。

**Q：怎么让 Codex 更懂我的项目？**
A：认真写 `AGENTS.md`（第 5 节），把技术栈、目录、命令、禁区都说清楚；并用技巧 4 让它持续补充。

**Q：我在 Windows 上用需要注意什么？**
A：直接用 Codex 桌面应用即可：ChatGPT 账号登录，权限从三档模式里选，沙箱由应用托管；需要 Linux 原生环境时在设置里切到 **WSL2**。高权限（Full Access）任务仍建议放进容器或一次性 VM。

**Q：能同时做好几件事吗？**
A：能。多开**线程**并行推进，每个线程独立 worktree，互不影响。
